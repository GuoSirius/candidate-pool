## 批次 A：闭环验证（先行，数据是后续一切调参的地基）

### A1. 三口径收益纯函数 `eod/lib/verdict.js`（复杂度：低）
- 输入：候选日 T 的开盘价 + 后续 K 线（腾讯 fqkline，一次拉多日，无东财封 IP 风险）
- 输出统一结构：
  ```
  t0: { buyRet, hit }            // 已有（当日开盘买入收盘收益）
  t1: { date, buyRet, hit }      // T+1 收盘 / T 开盘 − 1，hit ≥ 2%（阈值入 config）
  t3: { buyRet, maxRet, hit3 }   // T+3 收盘口径 + 期间最高收益（波段口径）
  ```
- 验收：单测（构造 K 线用例）+ 用现有 10 天归档实测。

### A2. 盘前回填补 T+1/T+3（复杂度：低）
- **实现偏差（2026-11-09 落地时调整）**：补齐逻辑统一收进 `nextday_backfill.js` 的 `preopen` 管道（basis=当日开盘价），**不再改 `preopen_backfill.js`**——一套 verdict 逻辑覆盖四管道，18:30 任务自然覆盖，避免两处重复实现漂移。
- `preopen_backfill.js` 每天跑时顺带扫描「最近 10 个交易日归档中缺 t1/t3 的」补齐——**不新增调度**，18:00 任务自然覆盖。
- 盘前报告收盘区块加「T0/T1/T3 三口径命中率」汇总行。

### A3. 统一次日回填 `eod/nextday_backfill.js`（复杂度：中）★核心
- 调度：新增 WorkBuddy 自动化 **18:30**（盘前回填 18:00 → 游资 18:20 → 本任务）。
- 逻辑：扫最近 10 个交易日，给三类归档补 `verdicts` 段（追加式，旧归档缺段不报错）：
  - 尾盘 `eod/data/eod/eod-<日>.json`（含 -obs）：每候选 t1/t3
  - 次日选股 `data/snapshot-<anchor>.json`：每触发票 t1/t3
  - 游资票 `eod/data/hotmoney/hotmoney-<日>.json`：每游资票 t1/t3
- 产出：`eod/data/perf-weekly.json` 滚动聚合（按管道 × 按票池）。

### A4. 游资表现统计 + 名单升降级依据（复杂度：中）
- hotmoney 报告「游资·近N日汇总」加列：介入票 T+1/T+3 平均收益与胜率（从 verdicts 聚合）。
- 报告新增「名单管理建议」区块（数据驱动、**只建议不自动改**）：
  - 晋升：观察席位 ≥3 天出现 且 介入票 T+1 胜率 ≥ 50% → 建议晋升（附名单）
  - 降级：一线/二线 近 N 日介入票 T+1 胜率持续 < 30% → 建议降级观察
  - 人工确认后改 `eod/data/hotmoney/hotmoney-registry.json`（add/remove 覆盖文件）即生效。

### A5. 尾盘报告加命中率区块（复杂度：低）
- 尾盘重渲染/回填报告头部加「近 N 日入选票 T0/T1/T3 命中率」汇总。
- **回答「ρ≈0.04 怎么处理」**：可以回填，且这正是迭代依据——verdicts 攒到 ≥20 个交易日后，批次 D 的周六简报按 5 个分项分组统计次日收益（分项分组回归），用数据调整 weights（p1-p5）/minTotal/涨幅桶。在此之前**不动权重**，避免小样本误调。

### 批次 A 验收
- 三份报告出现真实命中率数字；perf-weekly.json 生成；自动化 18:30 建立并 PAUSED→试跑→ACTIVE。

## 批次 B：环境闸 regime.js

### B1. `eod/lib/regime.js`（复杂度：中）
- 东财 push2 公开接口拉：涨停/跌停家数、连板高度、炸板率、涨跌家数、两市成交额、上证涨跌。
- 输出 `{ label: '强市/正常/弱市/冰点', detail }`，阈值入 config，失败降级留空（不阻断各管道）。
- 接入：盘前/尾盘/次日选股/hotmoney 四份报告头部加环境标签；gen_candidates 的市场宽度「暂不可用」用真实数据替换。
- 弱市行为：报告 callout 提示「建议 minTotal 临时 +5 / 降低仓位」，**只提示不自动改阈值**（自动改不可控）。

### B2. 情绪日报联动（复杂度：低）
- 情绪日报自动化（现 PAUSED 23:30）改为：读当日 regime 数据 + 各管道结果摘要（尾盘入选/次日触发/游资动向）+ pulse 消息面 → 生成日报并推送。改为 ACTIVE 后与管道形成闭环。

## 批次 C：协同与行动闭环

### C1. 盘中两时点对比 + 行动闭环（复杂度：中）
- 尾盘 14:30 观察报告新增「盘中预警对比」区块：读当日 10:30/11:30 两份 `-intraday.json`，分三组——
  - **两时点都在**：信号最可靠 → 行动标注「可提前挂单观察」
  - 11:30 新出现：尾盘确认后再动手
  - 10:30 有 → 11:30 消失：预警失效，弃
- 14:50 正式口径 stats 加 `intradayOverlap`（盘中预警票最终入选率），验证盘中预警价值。

### C2. 观察池自动维护 `eod/pool_reflow.js`（复杂度：中）
- 调度：**18:40**（nextday_backfill 之后）。
- 写回来源（带标签）：尾盘正式 TopN 且 T+1 命中、R01 触发、一线游资介入、盘前超预期。
- 淘汰：连续 5 个交易日未触发任何条件自动移出；上限 60 只，超限按最近触发时间淘汰。
- candidates.json 结构扩展 `meta: {sources, addedAt, lastTrigger}`，gen_candidates 兼容旧格式。
- **先 dry-run 一周**（只出 diff 报告不写回），确认后再全自动。

### C3. 统一收盘日报（可选，复杂度：低）
- **18:50** 汇总当天：盘前命中（T0/T1/T3）/ 尾盘入选 / 次日触发 / 游资动向 / 情绪标签 → 一页 HTML 推送。
- 依赖批次 A/B 的数据就位。

## 批次 D：配置统一规范（复杂度：低）

### D1. 配置规范文档 `docs/config-convention.md`
- 统一分区模板：`session / market / rules / score / exclude / group / store / report / notify`（对齐 preopen.config 的编号分区 + 每阈值注释口径的范式）。
- 共享段下沉：`market` 抓取参数（batch/concurrency/retries/timeout）抽 `eod/config.base.js`，各 config spread 合并 + 局部覆盖。

- **不破坏性重命名**：字段名不改（避免动全链引用），只对齐分区、补注释、下沉共享段。

### D2. 周六胜率回归简报（复杂度：低）
- WorkBuddy 自动化 **周六 10:00**：跑分析脚本（读 perf-weekly.json + verdicts），按管道/分项/游资三个维度出简报推送。
- 前置条件：verdicts ≥ 20 个交易日才输出回归结论，否则只报样本量。

## 附录 A：体系审计结论（2026-11-09，原独立文档已并入本文）

> 范围：盘前选股+回填 / 盘中机会 / 尾盘选股（观察+正式）/ 盘后次日选股 / 游资席位扫描 / 支撑层（pulse、行业映射、notify）。
> 结论先行：**单条管道工程质量都很扎实（时段守卫、数据闸门、幂等覆盖、原子写、日志归位全齐），最大短板在「横向」——闭环验证只有盘前一条、管道之间是孤岛、没有大盘环境闸。**

### A.1 逐管道核对（审计时点快照，缺口 1/2/3 已由批次 A/B 落地消掉）

| 管道 | 调度 | 优点（已核对代码） | 弱点 |
|---|---|---|---|
| 盘前选股 `preopen_screener` 09:25 | WorkBuddy | P1-P3 打分 + P04 门槛双轨；nearMiss 贴线归档供调参；全市场/观察池双 scope | 回填只验证「当日」，无 T+1/T+3 延迟收益口径；首次部署依赖 03:00 基线预计算 |
| 盘前回填 `preopen_backfill` 18:00 | WorkBuddy | 命中闭环 + 买入机会四态 + 上榜/游资标注；重渲染含收盘区块 | 仅盘前有此闭环（见横向缺口 1） |
| 盘中机会 `tail_screener --intraday` 10:30/11:30 | WorkBuddy | 收盘预估量比估算；强制 no-notify 不写 D1 | 纯预览无行动闭环；两时点结果无对比视图 |

| 盘后次日选股 `gen_candidates` 16:00（Actions 15:37 兜底） | WorkBuddy + Actions | 工程最完整：G 常量随快照留档、数据健康度闸门、WAF 退避梯度；做过一次人工回测调参（CHG_MIN 3→4，docs/backtest/01） | 观察池手工维护；市场宽度硬编码 error（批次 B 已消掉） |
