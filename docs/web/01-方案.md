# Web 前端（Vue3 + Vite PWA）

> **一句话**：只读查询前端，消费 [`../api/01-方案.md`](../api/01-方案.md) 的接口，提供
> 「候选列表 / 全部标的 / 复盘统计 / 规则释义 / 个股复盘」五个页面，支持 PWA 安装到手机桌面。
> **生产环境由同一个 Pages 项目的 Functions 同源提供 `/api/*`**，无需跨域。

## 1. 目录与依赖

| 文件 | 作用 |
|------|------|
| `web/package.json` | `vue` / `vue-router` 运行时；`vite` / `@vitejs/plugin-vue` / `vite-plugin-pwa` / `vue-tsc` 开发依赖 |
| `web/vite.config.ts` | Vite + Vue 插件 + PWA；`server.proxy` 把 `/api` 代理到 `wrangler dev`（:8787），免跨域 |
| `web/src/api/client.ts` | 统一 fetch 封装，**读业务码判定**（200=成功，1000x=业务错误，非 200=传输异常） |
| `web/src/api/types.ts` | 与 Worker `types.ts` 对齐的前端镜像类型 |
| `web/src/views/` | `RunsView`（候选列表）/ `AllStocksView`（全部标的）/ `StatsView`（复盘统计）/ `RulesView`（规则释义）/ `StockView`（个股复盘）/ `TailView`（尾盘候选） |
| `web/src/constants/glossary.ts` | 规则 / 档位 / N 日周期 / 字段释义的**唯一事实来源**，所有页面统一引用 |
| `web/src/utils/date.ts` | 日期工具（dayjs + `Asia/Shanghai`），如「近一月」区间计算 |
| `web/src/utils/sort.ts` | 表格点列头排序的统一实现 `useColumnSort` |
| `web/src/utils/format.ts` | 展示格式化（含 `tailModeLabel()` 口径标签） |
| `web/functions/` | Pages Functions：把 `/api/*`、`/health` 转发给共享 Hono app |
| `web/wrangler.toml` | Pages 项目配置：`pages_build_output_dir` + D1 绑定（与 worker 同一个库） |
| `web/public/_routes.json` | 限定 Functions 只接管 `/api/*` 与 `/health`，其余走静态资源 |
| `web/scripts/deploy.mjs` | 一键发布脚本：构建（注入 `VITE_API_BASE`）+ wrangler 推送 Pages，复用 worker 的 wrangler |

## 2. 页面与口径

| 页面 | 路由 | 主要能力 |
|------|------|----------|
| 候选列表 | `/` | 锚定日下拉（倒序）、档位过滤 + 关键词搜索、分页；量比 / 换手率 / 流通市值 / 总市值等列；进详情返回时恢复列表状态 |
| 全部标的 | `/stocks` | 按个股汇总历史入选：入选次数 + 各档数量（重点 / 次级 / 条件 / 排除）+ 首次 / 最近入选日；**列头可排序**，默认最近入选倒序；关键词搜索 |
| 复盘统计 | `/stats` | **默认最近一月**（可切近三月 / 全部）；各档命中率（每格**上行胜率、下行平均收益**，避免表过宽）；平均收益走势（N1–N10 全量，**可勾选 / 取消周期**）；锚定日明细（**倒序**）；统计口径 |
| 规则释义 | `/rules` | R01 / R07 / R05 门槛、四档划分、判定标记位、**N1–N10 全量周期一览**、字段释义、统计口径 |
| 个股复盘 | `/stock/:code` | 档案 / 备注、各周期复盘汇总（逐 N 样本 · 均值 · 最佳 · 最差）、每期入选的 N 列全量表现 |
| 尾盘候选 | `/tail` | 尾盘选股结果：运行记录 / 候选主表（六维打分分两组呈现）/ 口径对照 / 分行业明细 |

> 口径说明集中在 `web/src/constants/glossary.ts`，所有页面统一引用——改一处即全站生效，
> 避免「有的页面只写到 N5」这类不一致。

### 若干硬约定（改动前先看）

| 约定 | 说明 |
|------|------|
| 排序 | 走 `web/src/utils/sort.ts::useColumnSort`。`initialKey: null` = **保持数据源顺序**（候选池后端返回「档位分组 + 组内涨幅降序」，有业务含义，不能被默认排序键打散）；有固定梯队顺序的列取 `TIER_ORDER` 下标当数值排 |
| 空值 | 排序时**空值恒排最后，不随升降序翻转** |
| 序号列 | 数据表首列统一「序号」，语义是**当前展示顺序**（排序/筛选后重排，**不是记录身份**），故**不可排序**；分页表跨页连续 |
| 口径标签 | 一律走 `format.ts::tailModeLabel()`（formal=正式 / observe=观察 / **未知原样显示**）。**别用 `else` 兜底成「观察」** |
| `<colgroup>` | `<col>` 数必须等于 `<th>` 数（曾 11 对 12，错位把「总分」撑到 19%） |
| 移动端 | 行少列多的记录表 → 翻转成 **6 列 grid 紧凑卡片**（**禁止回到「一行一字段」**）；列极多的宽表 → **不翻转**，`overflow-x:auto` + `min-width` |
| 规则释义 | **只活在 `/rules`**，其他视图只留一行 + `<router-link to="/rules">` |

## 3. 本地开发

```bash
cd web
npm install
npm run dev          # 默认 :5173，/api 自动代理到本地 Worker（需另开终端跑 worker 的 npm run dev）
```

> 前端 `npm run dev` 与 Worker `npm run dev` 两个终端并行：前端拿 `/api/*`，Vite 代理到 Worker 的 :8787。
> 想直连线上数据就不必起 worker，把 `web/deploy.config.json` 的 `apiBase` 临时指向 Pages 地址即可。

## 4. 发布

一条命令：根目录 `npm run deploy`（= `cd web && npm run deploy`）。
脚本以 `web/` 为 cwd 执行，wrangler 自动发现同级的 `web/functions/` 与 `web/wrangler.toml`
—— **一次发布同时上线静态资源与 API**。

完整参数、首次准备、排查见 [`../../DEPLOY.md`](../../DEPLOY.md)。
