# 选股体系审计（2026-11-09）

> 范围：盘前选股+回填 / 盘中机会 / 尾盘选股（观察+正式）/ 盘后次日选股 / 游资席位扫描 / 支撑层（pulse、行业映射、notify）。
> 结论先行：**单条管道工程质量都很扎实（时段守卫、数据闸门、幂等覆盖、原子写、日志归位全齐），最大短板在「横向」——闭环验证只有盘前一条、管道之间是孤岛、没有大盘环境闸。**

## 二、横向缺口（优先级排序）

1. **统一次日回填 `nextday_backfill`**（价值最高）：尾盘/次日选股/游资票共用一个 T+1 命中统计器——开盘买入、开盘持有至收盘、3 日持有三口径；每周胜率表自动生成，反哺各 config 阈值。preopen_backfill 已是现成模板，抽公共 lib 即可。
2. **游资胜率表**：hotmoney 日档已存全部席位买卖，join 次日 K 线即可得「每位游资近 N 日介入票的平均收益」→ 报告加命中率列，观察名单晋升/一线降级都有数据依据。
3. **市场情绪闸 `regime.js`**：涨停家数/炸板率/涨跌停比（东财 push2 公开接口）→ 各报告头部加环境标签（强/中/弱市）；弱市自动抬高 minTotal 或提示空仓。gen_candidates 的市场宽度「暂不可用」顺带补上。
4. **观察池自动回流**：尾盘 TopN、R01 触发、游资介入的票自动写回 candidates.json（带来源标签 + N 日未触发自动淘汰），观察池从手工维护变半自动。
5. **统一收盘日报（18:50）**：一页汇总当天盘前命中率 / 尾盘入选 / 次日初筛 / 游资动向 / 情绪标签——现在要看 5 份报告。
6. （可选）盘前竞价增量监控 9:20–9:25（现在只有 9:25 一次性快照）。

## 三、小修清单（低风险顺手改）

- **tail 回放污染 runs[]**：`--replay` 的 raw 重算路径没有 skipStore，重渲染会把回放当一次正式运行写进 runs[] 历史（2026-11-09 重渲染时 runs 被截断，-355 行）。修：该路径传 skipStore。
- gen_candidates 市场宽度 error 字符串硬编码 → regime.js 落地后自然消掉。
- hotmoney `--date` 跑历史日时也会 union 席位进快照（首跑回补已发生一次，行为可接受；如需严格可只在锚定日 fresh 扫描时更新快照）。

## 四、路线图建议

- 第二批（环境）：regime.js 情绪闸。
- 第三批（协同）：观察池自动回流 + 统一收盘日报。
