## 2. 🔴 Blocker（必须修）

### 2.1 `--replay` 离线重算会把回放当正式运行写回权威归档

**位置**：`eod/tail_screener.js:145-151`（调用）、`:373-400`（`emitResult` 落库段）、`eod/lib/store.js:173,191`

```js
// runReplay 命中 raw 的自包含重算分支
return emitResult({
  ..., skipRaw: true,          // ❌ 唯独漏了 skipStore
  stamp: doc.stamp || false,
});
// 对照：无 raw 的「仅重渲染」分支 :188 明确写了 skipStore: true
```

**为什么错**：`emitResult` 用 `if (!p.skipStore)` 包住 `saveRun` → `saveRaw` → `syncTailRun`。漏传后一次回放会：

1. `saveRun` 整文件覆盖同名主存档，并把一条 `at: nowBJ()` 的伪运行追加进 `runs[]`；`store.js:173` 的 `slice(-keepRunHistory)`（20 条）会**挤掉真实运行记录，且不可逆**；
2. `syncTailRun` 用回放结果覆写 D1 / 本地库（`:390-400`）；
3. 重写报告 + 重发微信/邮件（`:408-427`）。

更危险的是叠加 **重算口径错误**：`:137-138` 用 `sessionState({ now, marketDate })` 现算 `segFrom`，**未传 `intraday`**。盘中存档 `cutAt=1035` 会被算成尾盘起点 `1430`，`tailMetrics` 回退滞后 255 分钟 > `SEG_START_LAG_MIN`，全部判 `data_gap` → **0 候选**，于是原存档 `records` 被写成空。只读实测：`eod/data/eod/eod-2026-10-13-intraday.json` 与同名 raw 均在线上，一条 `--replay` 即可触发。

**建议**：
- 回放分支一律 `skipStore: true`（一行，立刻止血）；
- `segFrom` 直接取 `lastRun.segFrom` 或 `records[0].tail.segFrom`（旧分支 `:182-183` 已有正确逻辑），不要现算 `sessionState`；
- 若确需「重算后另存」，给 `saveRun` 加显式 `source/allowHistory`，写到独立文件名，绝不追加 `runs[]`。

> 关联：`docs/system-plan-2026-11-09.md` 附录 A.3（原独立审计文档 §三）已把「tail 回放污染 runs[]」列为小修项。本轮据完整调用链把它**升级为 🔴**：它不只是多一条历史，而是会用 0 候选结果覆盖主存档、覆写 D1、重发通知。

### 2.2 recency guard 的 `run_at` 不是「数据生成时刻」，护栏失效

**位置**：`db/normalize.js:57,114` / `db/persist.js:12-28,37` / `gen_candidates.js:427`

```js
// gen_candidates.js:427 —— 快照自带真实生成时刻
const snap = { anchor, target, ..., generatedAt: nowStr(), ... };

// db/normalize.js:57 —— 入库时却被丢弃，改用「执行时刻」
const ts = fmtNow();   // 北京时间 YYYY-MM-DD HH:mm:ss
const run = { anchor_date: anchor, target_date: target, run_at: ts, ... };
```

**为什么错**：`persist.js:12-15` 的注释与 `PICK_Q` / `PRICE_Q` 的 `WHERE excluded.run_at >= pick_record.run_at OR ... IS NULL` 都假定 `run_at` 是**快照新鲜度**。实际它等于「这次入库跑得多晚」。可复现：

| 时刻 | 动作 | 写入的 `run_at` | 护栏判定 |
|------|------|-----------------|----------|
| 09:00 | `write_live.js` 实时入库（正确数据） | 09:00 | — |
| 18:00 | `db/backfill.js --both` 重放一份**残缺旧快照** | 18:00 | `18:00 >= 09:00` ✅ 放行 |

于是旧数据把新数据顶掉，且 `RUN_Q` 是 `INSERT OR IGNORE`、`BASE_Q` 亦然，全程无告警。2026-10-22 评审把「双端写入的 run_at 时效护栏」列为**设计亮点**，本轮据代码复核**予以撤回**：SQL 正确，喂进去的时间戳不对。

**建议**：`const ts = snap.generatedAt || fmtNow()`，并校验其为北京时间字符串（`time.now()` 口径）；`picked_at` 可继续用 `now()` 表示入库时刻，两者语义分开。补一条自测：两份同 `anchor_date`、不同 `generatedAt` 的快照逆序入库，断言库中保留 `generatedAt` 较新那份。

### 2.3 三份报告共用的 `b()` 未编码属性，硬编码文案含裸双引号

**位置**：`eod/lib/report_fmt.js:15`、`preopen_report.js:280`、`hotmoney_report.js:108`、`report.js:263-284`

```js
function b(zh, en) { return `<span data-zh="${zh}" data-en="${en}">${zh}</span>`; }
// preopen_report.js:280 的 zh 内含：<b class="sn-self">  ← 双引号
```

**为什么错**：`data-zh="信号分项：<b class="` 会在 `class="` 处提前闭合，后面的 `sn-self">…` 变成一堆游离属性。默认中文首次渲染用的是元素内容 `${zh}`（完整），但**切到 EN 再切回时** `apply('zh')` 从 `getAttribute('data-zh')` 取回残缺值并赋给 `innerHTML`，整段「分项说明」只剩开头几个字。英文侧同理：`hotmoney_report.js:108` 的 `"New seat"`、`report.js:263` 的 `"${esc(sector)}"` 会截断 `data-en`。

同一份 `b()` 被 `report.js` / `preopen_report.js` / `hotmoney_report.js` 共用，改一处影响全部；文件头注释也只说「参数为未转义文本」，没有约束「不能含裸双引号」。**外部数据多数调用点已 `esc()`（如 `:316` `b(esc(n), esc(n))`），故当前主要是内部 HTML 片段破坏，不是已证实的 XSS；但任何外部字符串未经 `esc` 进入 `b()` 即形成属性注入面。**

**建议**：
- 给 `b()` 的属性值单独做引号编码：`data-zh="${attr(zh)}"`，`attr()` 只把 `"` → `&quot;`（保留 `< >` 以维持粗体，`getAttribute` 会自动还原）；
- 把 `preopen_report.js:280` 的 `class="sn-self"` 改回单引号，与 `report.js:284` 对齐；
- 更彻底的做法是 `apply()` 用 `textContent` + CSS 控制样式，但需全量验证三处调用点。

### 2.4 盘前时段守卫缺周末粗筛，`watchlist` 分支连行情日期终筛也没有

**位置**：`eod/preopen_screener.js:74-86`、`:211-234`

```js
function sessionState({ now, marketDate, force }) {
  const hhmm = now.hour() * 100 + now.minute();
  if (hhmm < from || hhmm > to) return { ok: false, ... };
  if (marketDate && marketDate !== today) return { ok: false, ... };  // 仅当传入才判
  return { ok: true, tradeDate: marketDate || today };                 // ❌ 无 weekday 检查
}
```

**为什么错**：`now` 来自 `dayjs.tz()`（`:171-173`，时区本身没问题），但函数完全不检查 `day()`。周六 09:25 落在窗口内 → `ok:true, tradeDate='2026-11-07'`。

| scope | 第二遍守卫 | 周六 09:25 的实际行为 |
|-------|-----------|----------------------|
| `universe`（默认） | `:232` 用 `snap.meta.marketDate` 复核 | 能拦住，但已**白跑 500 批全市场请求**，徒增 WAF 风险 |
| `watchlist` | ❌ `:219-223` 后无任何复核 | 拿上周五陈旧竞价报价算基线、打分、落库、推送，**无告警** |

对比 `eod/lib/trading.js:175` 已实现 `day===0||day===6` 粗筛，此处属遗漏而非设计取舍。

**建议**：复用 `trading.js` 的 `nowBjt()` + 周末判断，或在 `sessionState` 开头加 `if (now.day()===0 || now.day()===6) return {ok:false, reason:'非交易日'}`（`--force` 分支仍应可覆盖）；`watchlist` 分支补一次基于 `q.stamp` 的 `marketDate` 复核。

`hotmoney_store` 虽用了原子写，但 tmp 名固定 `${f}.tmp`，两个 `hotmoney_scan` 进程同时跑会争抢同一个 tmp，`renameSync` 互相踩出 ENOENT。

**#11 通知层全链路无超时**（`notify.js:56-72` 的 `https.request`、`101-135` 的 `tls.connect`、`scripts/trigger-github-dispatch.mjs:122` 的 `fetch`）：三者都只在 `error`/`end` 时 settle。Server酱 / 163 SMTP / GitHub API 若建连后不发首字节，或 DATA 后不回 250，`await notify()`（`tail_screener.js:426`、`preopen_screener.js:373`）**永不返回**——报告已落库但 `emitResult` 不结束，进程因 socket 保活不退出，定时链路静默挂死。这与上次评审「整封 base64 一次写」的取舍无关，是独立的连接层缺陷。建议 `req.setTimeout(15000, () => req.destroy(...))`、`socket.setTimeout`、`fetch` 加 `AbortSignal.timeout(15000)`，并对每个渠道做 `Promise.race` 兜底。

**#12 收盘表 chip 复用**：`preopen_report.js:404` 把含 `@best`/`@top3` 的 `labelChips` 原样给收盘区，而 `closeRowHtml`（`:91`）的行没有 `data-best`/`data-grank`（全文件仅 `:68` 的 `rowHtml` 有）。`:568-569` 的 `cWant` 对收盘行全判 false → `renderClose` 把 `closeBody` 全部 `hidden=true`，**整张收盘表变空**。建议给收盘行补属性，或为收盘区单独生成剔除这两个 chip 的工具栏（收盘回填本无「组内排名」语义）。

**#13 `@hm:` 分隔符**：`data-hm="名字1|名字2"`、chip `data-lfilter="@hm:A|B"`，前端 `split('|').indexOf(...)`。名字含 `|` 时行被拆成两段，chip 点了全空、点 `@hm:A` 反而误命中；`h.name` 为空时 `hotNameCounts`（`:303`）以 `'undefined'` 为 key 生成无效 chip。建议 `data-hm` 改存 `esc(JSON.stringify(names))` + `JSON.parse`，chip 值用 `encodeURIComponent(n)`，并先 `trim()` 过滤空名。注意 `& < > "` 两边各 `esc` 一次、`getAttribute` 各还原一次目前是能匹配的，别一并改坏。

**#14 游资报告口径**：`hotmoney_report.js:111` 中文 `(t.net/1e4/10000).toFixed(1)+'万'` 实为 `/1e8`（亿）却标「万」，与同段英文 `fmtAmt(t.net).txt`（`1.20亿`）和正文表格 `:204` 矛盾；`:80` 的 `nameOrder` 只取锚定日名单，却被 `:97-98` 的 `nameChips()` 硬编码用于窗口表 `:218`，只在历史日出现的游资无法生成 chip。建议中文分支统一用 `fmtAmt`，`nameChips` 按传入 `counts` 的 keys 生成。

**#18 `--now` 校验**：`preopen_screener.js:171-173` / `tail_screener.js:275-277` 用固定下标或宽松解析，`--now "2026-9-18 14:55"` 会产生 dayjs Invalid Date；`NaN < 570`、`NaN > 1080`、`NaN===0||6` 全为 false，**整个时段守卫被绕过**。建议严格解析并在 `sessionState` 入口加 `if (!d.isValid()) return {ok:false}`。另 `--wait` 与 `--intraday`/`--now` 同时出现时语义冲突，`--wait` 等到真实 14:50 会走 cut 分支写正式文件、而 `--intraday` 已强制 `noNotify` → 静默覆盖正式口径文件，建议加互斥校验。

**#17 时区**：`pulse/watch.js:13` 裸 `require('dayjs')`，`isActive()`（`:25-28`）用它比较 `08:30–16:35`。`time.js` 的 `dayjs.tz.setDefault` 不改变裸 `dayjs()` 的本地时区语义；GitHub runner 为 UTC 时整个交易时段被判窗口外、每 3 分钟空转。同目录 `collect.js:15` / `lib/store.js:17` 都手算 `+8h`，说明作者知道要转北京，唯独此处漏了。建议统一 `require('../time')`。

**#19 迁移空吞**：`db/persist.js:53` 注释说只忽略「列已存在」，但网络抖动、`no such table`、权限不足、D1 `/query` 报错同样被吞；且 WeakSet 已把该 client 标记完成，本进程不再重试，最终报 `no such column: run_at` 时与根因脱节。建议仅当错误信息匹配 `duplicate column name|already exists` 才忽略。
