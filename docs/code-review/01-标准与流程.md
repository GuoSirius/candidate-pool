> 目的：把"代码质量参差不齐"收敛为**可检查的清单**和**可执行的流程**，而不是靠自觉。
> 适用范围：本仓库全部代码（`gen_candidates.js` 等核心管线、EOD 尾盘、`db/`、TS 层 `worker/` `web/`）。
> 维护方式：结构性改动后由 reviewer 同步更新本文件，保持与 `docs/*/01-方案.md` 一致。

## 1. 审查标准（Checklist）

按维度分组。每条标注级别与**本项目红线/示例**，让 reviewer 有抓手。

### 1.1 正确性 🔴（错了就是错的，必须拦）

- **时区/时点**：任何涉及"交易日/盘中/周末顺延"的判断，一律 `dayjs.tz`，**禁止**用 `new Date().getDay()/getHours()` 这类读机器本地时区的方法。
  - 红线依据：`gen_candidates.js:90-95` 注释已写明换台非 +8 机器就会判错。
- **行情字段映射**：裸下标（`f[44]` 流通市值 / `f[45]` 总市值 / `f[31]` 涨幅）**必须**集中为具名常量，并附实测核对（中国石油 `44=17568亿 / 45=19857亿` 反例）。
  - 改前必读 README「接口的几个坑」表。漏看极易把"换手率暴涨 100 倍""全年涨幅"当"当日涨幅"。
- **复权 / 成交量单位口径**：日线取**前复权** `qfqday`；主板/创业板按**手**、科创板 `sh688/sh689` 按**股**（金山办公反例）。
  - 红线依据：`gen_candidates.js:272-288`。
- **数组排序方向**：腾讯 K 线**升序**返回，内部必须翻转为降序，`hist[0]` 才是前一交易日；误用升序会把"日涨幅"算成"近一年涨幅"。
  - 红线依据：`gen_candidates.js:209-237`。

### 1.2 安全 🔴

- **输出编码**：所有外部数据（股票名、排除原因、动态字符串）写入 HTML 前**必须**经 `escapeHtml()`。当前 `b(zh,en)`（`gen_candidates.js:587`）直接注入属性与 innerHTML，API 名若含 `"`/`<` 可破坏结构。
  - 一行防御：新增 `function esc(s){return String(s).replace(/[&<>"']/g,m=>({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[m]))}` 并在 `b()` 内调用。
- **凭据**：`notify_config.json` / `db/.env` 不入库（已被 gitignore）；CI 走 Secrets。新增任何密钥一律走 Secret/环境变量，**禁止**提交明文。
- **SQL**：D1/SQLite 全部参数化（`db/clients.js` / `schema.sql`），禁止字符串拼 SQL。

### 1.3 健壮性 🟡（容易"看起来正常其实坏了"）

- **静默失败防护**：任何"失败会被下游当成正常结果"的路径，必须加闸门。参照 `gen_candidates.js:421-442` 的失败率红线——全量拦截不会产出"今日 0 触发"还照常推送。新加的网络/数据链路沿用此模式。
- **重试/退避**：网络错误短退避、WAF 命中**长退避**（参照 `WAF_BACKOFF`），禁止盲目短重试（拿到的仍是拦截页）。
- **边界兜底**：空数组 / `NaN` / `null` 字段必须处理，沿用现有 `num()`/`yi()`/`pct()` 的 `isNaN → '—'` 风格，新代码不要裸 `toFixed`。

### 1.4 可维护性 🟡

- **单文件规模**：单文件 **> ~400 行**或"一个文件承担多职责"（解析/规则/IO/渲染）**必须拆分**。
  - `gen_candidates.js` 是待治理对象：先抽 `rules.js`（R01/R07/R05 纯函数）、`render.js`（HTML 模板）、`net.js`（HTTP/K线/报价），`main()` 只做编排。拆分时**先补自测再拆**，保证行为不变。
- **阈值常量化**：所有门槛进 `G` 常量表（`gen_candidates.js:69-77` 已有），禁止散落魔法数字。
- **注释讲 why**：保持现有"接口坑"注释风格——说清**为什么**这样写，不只是**是什么**。

### 1.5 性能 🟡

- **并发受控**：用 `mapLimit`（已有，`gen_candidates.js:320-336`）控制并发，禁止无限制 `Promise.all` 打满接口（触发 WAF）。
- **快照体积**：快照剥离原始 `kline/minute` 大字段（已有），新增落盘字段同样评估体积。

### 1.6 测试 🔴（当前最弱，优先补）

- **关键纯函数必须有自测**：R01/R07/R05 判定、分类、字段映射、时区推算（`lastClosedTradingDay` 等）必须从 `gen_candidates.js` 抽出后配 `*.selftest.js`。
  - 这是当前**最大缺口**：规则改动没有任何自动回归保护。
- **自测规范**：沿用本项目约定——`check(name, cond, detail)` + 退出码 `0/1` + 纯函数 + 临时目录，**不引入测试框架**（保持零依赖哲学）。
- **坑即回归**：README「接口坑」表每新增一条，对应补一条断言，把"踩过的坑"钉死。

### 1.7 约定 🔴

- **提交信息**：Conventional Commits，`commitlint` 已强制（type 限 `feat/fix/docs/...`，小写，无句末点，header ≤100）。
- **Schema 变更**：改 `db/schema.sql` 后必须 `npm run db:migrate:both` 同步两端，**禁止**手改本地库或 D1。
- **文档同步**：结构性改动同步对应 `docs/*/01-方案.md`（💭，但强烈建议）。

## 2. 审查流程

### 2.1 触发与角色

- **触发**：所有进 `main` 的改动（包括自己改自己）一律走 **PR**；`daily-artifacts` 产物分支不审。
- **角色**：作者先按 §1 自审 → 至少 **1 名 reviewer**（小团队互审/隔日审即可）。Reviewer 对 🔴 有一票否决权。

### 2.2 CI 门禁（必过才能合并）

| 门禁 | 命令 | 作用 |
|------|------|------|
| 类型检查 | `npm run typecheck` | `worker/` `web/` TS/Vue 类型 |
| 自测 | `npm run selftest` | paths/scaffold/tail/db 回归 |
| 打包校验 | `npm run pack:dry` / `verify:pack` | npm 包产物完整性 |

> GitHub Actions 的 `schedule` 实测不准（延迟 45min~12h），尾盘主通道是**本地计划任务**，Actions 仅备份——审查"定时类"改动时务必确认本地通道仍有效。

### 2.3 审查六步

1. **读 diff + 关联 docs**：改动是否动了"接口坑"相关代码？是否同步了 `docs/01-方案.md`？
2. **本地跑门禁**：`npm run selftest` + 涉及 TS 时 `npm run typecheck`。
3. **按 §1 清单逐项勾**：重点盯 🔴（时区、渲染转义、静默失败、规则单测）。
4. **盯三类高危**：① 静默失败（不报错但结果错）② 外部数据（API/HTML）③ 时区/口径。
5. **给结论**：`Approve` / `Request changes`，评论用 🔴🟡💭 标注并附 `文件:行号`。
6. **合并后 verify**：确认 `daily-artifacts` 当日产物正常、推送/落库未静默跳过。

### 2.4 Definition of Done（合并前全绿）

- [ ] CI 三门禁通过（typecheck / selftest / pack）
- [ ] §1 的 🔴 项全部满足，🟡 项有说明或已修
- [ ] 涉及规则/解析的改动有对应自测或已在 PR 说明为何暂无
- [ ] 涉及 schema 的改动已 `db:migrate:both` 并验证两端一致
- [ ] 提交信息符合 commitlint

### 2.5 本项目常见反模式（reviewer 必须警惕）

| 反模式 | 表现 | 正确处理 |
|--------|------|----------|
| 静默换目录 | 改 `paths` 默认导致产物写到别处 | 跑 `paths.selftest.js` 钉死 |
| 静默 0 触发 | 全量拦截却产出"今日 0 候选"并推送 | 失败率闸门 + 退出码 1 |
| 裸索引映射 | `f[44]` 直接用，不看 README 坑表 | 具名常量 + 实测核对 |
| 单文件巨石 | 一个 995 行文件包揽一切 | 按职责拆分 + 先测后拆 |
| 渲染无转义 | API 数据直进 innerHTML | `escapeHtml` 再注入 |

## 3. 落地建议（增量推行，不停工大重构）

1. **先立规矩**：本文件 + PR 模板（`.github/pull_request_template.md`）即日起使用。
2. **第一优先补测试**：把 R01/R07/R05 + 分类 + 字段映射抽成纯函数并配 `*.selftest.js`。这一步直接消除"规则改动无回归"的最大风险。
3. **渐进拆分 `gen_candidates.js`**：先抽 `render.js`（HTML 模板）和 `rules.js`（规则判定），`main()` 留编排；每次拆分带自测，小步合并。
4. **一行防御**：加 `escapeHtml`，在 `b()` 与所有数据注入点调用。
5. **定期回顾**：每季度对照本文件过一遍 🟡 项，把已治理的从"建议"升为"红线"或归档。

> 原则：**审查是教人，不是卡人**。每条 🔴 都解释 why，每条建议都给可操作的改法。
