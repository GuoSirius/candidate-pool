## 2. 🔴 Blocker（建议先修）

### 2.1 回扫窗口按文件数截断，tail 只覆盖 5 个交易日

**位置**：`eod/nextday_backfill.js:62-71`（`listTail`）、`:203-218`（聚合）

```js
// listTail：正则同时匹配 eod-<日>.json 与 eod-<日>-obs.json，一天两档
return out.sort(...).slice(0, OPT.days);   // ❌ 这里数的是「文件」，不是「交易日」
...
byDay[entry.date] = aggDay;                 // ❌ 同日两份，后者覆盖前者
```

**只读实测**（`eod/data/eod/`）：前 10 份 = `11-09 / 11-06 / 11-05 / 11-04 / 11-03` 各 formal+obs → **5 个不同交易日 / 10 个文件**；`byDay` 只有 5 个键。而 `nextday.config.js:16` 写 `window.days: 10`，`report.js` 命中率 callout 文案写「近10日入选票命中率」，盘前/次日/游资三条管道都是 10 个交易日。

**为什么严重**：`perf-weekly.json` 是批次 D 调参的唯一数据地基（plan §A5：攒 ≥20 交易日后按分项回归调权重）。tail 样本窗口与其余管道不一致、且同日归档互相覆盖，会让「按管道对比胜率」从根上不可比；这是一条**不报错、不损坏文件、但结论错**的路径，查起来极贵。

**建议**：按日期去重后再取最近 N 个交易日（`Map<date, entries[]>`）；`byDay` 的键带口径后缀（`-obs`）或先把同日两份合并成一组再聚合；补一条自测断言「`window.days=10` 时 tail 覆盖 ≥10 个不同交易日」。

### 2.2 `breadth.halt` 把 3 万个代码槽位算成「停牌」

**位置**：`gen_candidates.js:428` → 渲染 `:623`；`market.js:187` 的 `slots: codes.length`

`expandCodes()`（`market.js:59-71`）展开的是**配置里枚举的代码段**，不是上市公司清单。按 `tail.config.js:21-30` 的 RANGES 求和：6000 + 2000 + 3999 + 2000 + 1000 + 10000 + 4000 + 1000 ≈ **29,999 个槽位**；实际 A 股有效报价约 5,400 只。于是

```js
halt: Math.max(0, (snap.meta.slots || 0) - snap.meta.valid)   // ≈ 29,999 − 5,400 ≈ 24,600
```

被直接渲染进市场宽度表的「停牌」列。未分配的号码、未上市、已退市、空槽位、解析失败、请求失败批——全部被算成停牌，且快照越不完整这个数越大（失败时反而「更合理」地虚高）。

**建议**：最小止血是 `halt: null`（渲染层显示「—」）并删掉这列；要真实值就让 `fetchBatch` 累计「有响应但 `parseQuote` 返回 null」的条数，或用上一交易日有效报价集合做差集。无论哪种，都别把 `slots` 当分母——它只是抓取配额，不是市场宽度。

### 2.3 K 线抓取失败被静默计成「待次日」，退出码恒 0

**位置**：`nextday_backfill.js:166-172`、`:184-186`、`:246-258`

```js
try { ... } catch (e) { kErr++; kCache.set(code, null); }   // 失败与「无数据」同形
...
if (!bars.length) { pending++; continue; }                  // 抓失败也走这里
```

`pending++` 无法区分「T+1 还没到」（正常）与「腾讯 fqkline 全线失败 / WAF / 端点变更」。全挂时日志是「待次日 N 条」，聚合照常基于旧 `verdicts` 输出、重渲染照常、`process.exitCode` 保持 0 —— 调度与微信通知都认为今天正常，胜率数据静默停更。这与 `01-标准与流程.md §1.3`「静默失败防护」红线冲突，而项目里已有现成范式：`fullMarketSnapshot` 的 `maxBatchFailRate` 熔断（`market.js:169-172`）。

**建议**：`kCache` 存 `{ rows, failed }`，把 fetch 失败单独计数；`kErr / needCodes.size > 0.3` 时 `process.exitCode = 1` + 明确告警，并跳过写回/聚合（避免用不完整数据覆盖 perf）；`pending` 只统计真正缺 bar 的记录。

## 4. 🟡 正确性 / 健壮性

**#8 `minifyHTML` 的「零语义风险」不成立** — `report_fmt.js:58` 的 `.replace(/\s*([{}:;,])\s*/g,'$1')` 会连 CSS **字符串内部**的空格一起删。只读实测：

```
输入  <style> .a::before { content: "a: b, c"; } </style>
输出  <style> .a::before{content:"a:b,c";}</style>
```

三份报告现有 CSS 里没有 `content:` / `url(...)`，所以**当前不触发**；但注释承诺「零语义风险」，后续任何人加一句带冒号/逗号的 `content`、`url(data:...)` 就会悄悄坏样式，且因为只在 `<style>` 内生效，很难联想到压缩器。建议只保留「`<style>` 内 `\s+ → ' '` + 去行首缩进」，不删 `{}:;,` 周围空白（体积收益有限）；并补一条自测把 `content:"a: b, c"` 钉死。

**#9 双语与转义** — `regime.badgeHTML(r, b, esc)`（`regime.js:84`）签名收了 `b`/`esc` 却完全没用，返回硬编码中文；三份报告切 EN 时环境标签与弱市提示仍是中文。`hotmoney_report.js:263` 的名单建议先 `esc(...)` 再传给 `b()`，而 `b()`（`report_fmt.js:20`）对属性又 `esc` 一次 → 双重转义，切 EN 再切回中文时 `&amp;` 会变成字面量。文件头注释已写明「参数为未转义文本」，这处是新增的违反。建议徽标用 `b(zh,en)` 包；名单建议把外部名字交给 `b()` 统一处理。

**#10 阈值与重复实现** — `hotmoney_scan.js:238` 与 `rerender.js:159` 各写一份 `win(arr, min)` 且硬编码 `2`，而 `nextday.config.js:19` 的 `t1HitMin/t3HitMin` 是可配的 → 改配置后游资胜率列不变。更值得治的是 `byTrader` 整套窗口聚合（~60 行）两处复制：今天新增的 T+1/T+3 字段就得改两边，下次还会漏。建议抽 `eod/lib/hotmoney_agg.js` 共享纯函数 + 从 config 读阈值 + 补自测。

**#11 空榜日串档** — `hotmoney_scan.js:170` 取 `const anchorDoc = days[0]`，`:189` 用 `store.saveDay(anchor, anchorDoc)` 落盘。`tradingDays()`（`:81-93`）在锚定日**空榜 / 非交易日**时会 `continue`，此时 `days[0].date` 是更早的交易日，却以 `anchor` 为文件名写入 → 该日归档被换成别日的 `records` + `seatChanges`，18:30 的 `rerenderHotmoney(anchor)` 会渲染错日数据。建议 `days.find(d => d.date === anchor)`，找不到就跳过 seatChanges 落盘。

**#12 未收盘 bar 被幂等冻结** — `lastClosedTradingDay`（`rules.js:55`）用 `hour < 15` 判收盘；15:00 刚过时腾讯 fqkline 可能仍返回当日未定格 bar，一旦写进 `verdicts.t3.date`，`hasComplete()`（`:55-57`）就永久跳过该记录，错误收益再不会被纠正。18:30 常规调度不受影响，风险集中在手动补跑 / 调度提前。建议 `hasComplete` 增加「`t3.date` 距今 ≥1 个交易日」，或定期 `--force` 重算近 3 日。

## 7. 设计亮点（值得保留）

- **`verdict.js` 三口径纯函数**：`barsAfter` 对降序 K 线 `filter → reverse → slice(0,3)` 取到的是 T 之后**最早** 3 根，边界（停牌缺 bar、脏 open、空数组）都覆盖；两份新增 selftest 实跑 **全绿**（verdict 27 项 / regime 12 项），且已挂进 `npm run selftest`。
- **去重与缓存**：`needCodes` 跨管道去重、`kCache` 进程内复用、`touchedFiles` 去重写盘，同票只抓一次、同档只写一次；`hasComplete` 的 t3 幂等判断简明有效。
- **失败降级不阻断**：`calcRegime` 覆盖不足返回 `null`、`gen_candidates` 全市场快照 `try/catch` 降级为「宽度暂不可用」、弱市只提示不自动改 `minTotal`——都守住了「辅助信号不拖垮主流程」的边界。
- **口径注释密度**：`nextday_backfill` 头部把四类 `basis`、盘中未收盘截断、`verdicts` 追加式兼容写得很清楚，是这份代码最容易维护的部分。
- **`b()` 属性编码修复**：上一轮 🔴 的最小改法落地正确，浏览器 `getAttribute` 自动解码实体，双语切换行为未回归。
