## 2. 🔴 Blocker（必须修）

### 2.1 股票代码被正则剥错——报告里全是 `h600519`

**位置**：`gen_candidates.js` 第 490 / 525 / 548 / 564 行（4 处写法相同）

```js
s.code.replace(/^[sh|sz]/, '')   // ❌ [sh|sz] 是字符集合 = {s, h, |, z}
```

**为什么错**：方括号在正则里是「字符集合」，不是「分组」。`[sh|sz]` 表示「首字符是 s / h / | / z 之一」，于是：

- `sh600519` → 剥掉首字符 `s` → **`h600519`** ❌
- `sz002594` → 剥掉 `s` → **`z002594`** ❌
- `bj300750` → `b` 不在集合里 → **原样保留 `bj300750`** ❌

**影响**：HTML 报告与核心结论里所有代码展示都是错的；4 处都这么写，属于**可见的输出正确性 Bug**。

**正确写法**：用分组而非字符类，并补上 `bj` 前缀：

```js
s.code.replace(/^(sh|sz|bj)/, '')
```

> 参考：尾盘侧 `eod/tail_screener.js:392` 用的 `c.code.replace(/^[a-z]+/, '')` 是对的（贪婪匹配首部小写字母，能完整剥掉 `sh`/`sz`/`bj`），可统一照搬。

### 2.2 `persist.ensureColumns` 的全局 `_migrated` 旗标会让「双端迁移」失效

**位置**：`db/persist.js` 第 42-53 行

```js
let _migrated = false;                                  // ❌ 模块级，跨 client 共享
async function ensureColumns(client) {
  if (_migrated) return;                                // 首个 client 执行后置 true
  _migrated = true;
  for (const sql of [...]) try { await client.query(sql); } catch (_) {}
}
```

**为什么错**：本机 `tail_screener` 默认走 `store_d1.targetArgv` 注入 `--both`，于是 `backfill`/`write_live` 在一个进程内对 **remote + local 两个 client** 各调一次 `persistSnap`。第一个 client 做完 `ALTER TABLE ADD COLUMN` 后 `_migrated=true`，第二个 client 的 `ensureColumns` 直接 `return`，**永远拿不到 `run_at` / `vol_ratio` 列**。

**现状只是被掩盖**：`resolveTargets` 把 remote 排第一，且本地库每次 `createClient` 都会重跑 `schema.sql`（自带这些列），所以本地侧恰好没暴露问题。但一旦顺序变化、或 remote D1 没跑过 `db:migrate`，第二个库的 `INSERT/UPDATE` 会因缺列失败——双写变单写且**静默**。

**修复建议**：把「已迁移」状态改成 **per-client**，而不是全局布尔：

```js
const _migrated = new WeakSet();
async function ensureColumns(client) {
  if (_migrated.has(client)) return;
  _migrated.add(client);
  for (const sql of [...]) try { await client.query(sql); } catch (_) {}
}
```

## 3. 🟡 性能瓶颈 & 应修隐患

### 3.1 HTTP 请求不复用连接（每次重建 TLS 握手）

**位置**：`gen_candidates.js:137` 与 `eod/lib/http.js:83` 的 `https.get` 均未传 `agent`。

**影响**：30000 只代码 × 6 并发、或 377 只 × 3 端（quote + kline + minute）≈ **1000+ 次全新 TLS 握手**。盘中全市场快照会更慢、更易被风控。

**建议**：引入 keep-alive 代理，复用 TCP/TLS：

```js
const keepAliveAgent = new https.Agent({ keepAlive: true, maxSockets: 6 });
https.get(url, { agent: keepAliveAgent, ... }, cb);
```

---

### 3.2 D1 `batch()` 既非事务、又每条语句一次 HTTP

**位置**：`db/d1client.js` 第 55-65 行

```js
async function batch(statements) {
  for (let i = 0; i < statements.length; i += BATCH_CONC) {
    await Promise.all(slice.map(s => post('/query', { sql: s.sql, params: s.params })));
  }
}
```

**影响**：`persistSnap` 一次给 remote 约 **377 picks + 377 prices + 档案 ≈ 760 条语句 → 76 波 × 10 并发 = 760 次网络往返**。
两个问题并存：

1. **慢**——全是独立网络往返；
2. **非原子**——中途失败会留下半截数据（本地 `sqlite_client.batch` 有 `BEGIN/COMMIT`，D1 侧没有等价事务）。

**建议**：
- 复核 Cloudflare D1 `/query` 是否真不支持 `statements` 数组（注释说 404，但值得再验一次）；
- 若不支持，则在一次请求里尽量多塞语句，并加整批失败重试，使写入至少在应用层可重试、可观测。

---

### 3.3 并发抓取共享「粘性端点指针」——单点 WAF 会级联全部请求

**位置**：
- `gen_candidates.js:186` `let _klineEp = 0;`（在 `fetchKline` 内被并发 worker 改写）
- `eod/lib/market.js:47` `_minuteEp = makeSticky(...)`（模块级）
- `eod/lib/market.js:353` `let _klineEp = 0;`（同上）

**为什么错**：`mapLimit` / `fetchMinutes` 会起多个并发 worker，**全部读写同一个模块级指针**。
- `_minuteEp.tryAll` 内某次 WAF 命中会 `pick.next()` 把全局指针推到下一台 → 所有在途请求瞬间一起换链路；
- `_klineEp` 的 `if (idx !== _klineEp) { _klineEp = idx }` 还是**非原子的读改写**。

**影响**：一次瞬态封禁可能把整批并发拖到降级端点，或触发无谓重试（实测教训里「被拦时静默慢跑比报错更危险」）。

**建议**：把粘性状态按「每次调用」隔离——将指针对象作为参数传入 `fetchKline` / `fetchMinute`，并发之间不共享；至少不要在并发调用间共用同一实例。

---

### 3.4 `write_live.js` 默认只写 remote，与尾盘不一致

**位置**：`db/clients.js` 的 `resolveTargets()` 无参数时 `wantRemote=true, wantLocal=false`；`db/write_live.js:24` 直接 `resolveTargets()`（不走 `store_d1.targetArgv`）。

**影响**：本机跑 `gen_candidates → write_live` 默认**只写 D1、不写本地 `db/local.db`**；而尾盘 `syncTailRun` 经 `targetArgv` 注入 `--both` 会双写。结果：本地库有尾盘数据、却没有候选池快照，复盘 / 离线查询会缺半边。

**建议**：让 `write_live` 也走 `targetArgv` 或显式 `--both`，使两端写入策略一致。

---

### 3.5 `notify.js` 整封邮件 base64 后一次性写入

**位置**：`notify.js` 第 143、163 行（`b64` + `socket.write(msg + '\r\n.')`）

**影响**：先把整封 multipart（含完整 HTML 报告附件，可 1–2MB）在内存里拼好再一次性 `socket.write`。大报告是一次**内存尖峰 + 单次巨量写入**，部分 SMTP 服务端对超大单写敏感。

**建议**：改为分块流式写入（按 base64 折行边算边写），避免一次性大缓冲。

---

### 3.6 `build_universe.js` 用裸 UA 且无 WAF 兜底

**位置**：`build_universe.js` 第 108-130 行（`getRaw` UA 为 `'Mozilla/5.0'`）

**影响**：本仓库 `eod/lib/http.js` 的注释明确说「残缺 UA 本身就是风控指纹特征」。此外 `fetchBatch` 拿到 WAF 跳转页时，正则匹配不到 `v_...` 就**静默少抓几只**，不会报错。

**建议**：复用主流程的完整浏览器 UA；对返回体做 WAF 嗅探重试（`looksLikeWaf` 已在 `http.js` 实现，可直接复用）。

## 4. 💭 Nits（可顺手改）

### 4.1 `new Promise(async (resolve, reject) => {})` 反模式
**位置**：`gen_candidates.js:125`、`eod/lib/http.js:69`。功能上能跑，但执行器内的同步异常会被吞、也不利于 unhandled-rejection 安全。建议改成普通执行器 + 内部 `await`。

### 4.2 `package.json` `engines` 声明失真
`package.json:94` 写 `node >=18`，但 `db/sqlite_client.js` 用 `node:sqlite`（需 22.5+）。在 18/20 上 `require('node:sqlite')` 直接崩。应改成 `>=22`。

### 4.3 `d1client.exec` 返回 `r[0]`，但 `cleanupLegacyModes` 读 `r.meta.changes`
`db/d1client.js:67` 的 `exec` 返回 `r[0]`；`store_d1.js:276` 却读 `r.meta.changes`。D1 `/query` 的 `meta.changes` 在结果数组**顶层**，`exec` 取 `r[0]` 读不到，于是删除计数总显示 `'ok'`（删除仍生效，只是日志看不见数量）。

### 4.4 `normalizeSnap` 的 `kline_fail_rate` 漏算纯 quote 失败
`db/normalize.js` 里 `err` 只数 `r.error`，而 `r.error` 来自 kline；quote 单独失败时不计入，失败率被低估（仅影响门禁统计，不影响数据正确性）。

### 4.5 主流程 `loadUniverse(limit)` 后被覆盖 + `fetchKline` 未短路
`gen_candidates.js` main 中 `const limit = universe.length;` 把 `--limit` 的语义冲掉（仅截断候选池、下游又覆盖）；且 `fetchKline` 在 `fetchQuote` 失败后仍无条件执行，浪费一次请求。建议对 quote 失败的票短路跳过 kline 抓取。

## 5. 设计亮点（值得保留）

- **时区统一**：全部业务时间走 `dayjs.tz('Asia/Shanghai')`，落库用 `YYYY-MM-DD HH:mm:ss`（无 Z），根治裸 UTC 偏移；交易日判定用「行情时间戳众数」而非维护节假日表，零维护覆盖休市 / 调休。
- **WAF 长退避 + 三主机粘性降级链**：重试压到 2 次，避免盘中空跑半小时（注释里的实测教训很到位）。
- **`store_d1` 的列清单派生占位符 + params 顺序**：从根上消除了 2026-09-21「33 列 / 32 个 `?`」的错位事故。
- **双端写入的 `run_at` 时效护栏（recency guard）**：避免陈旧离线数据顶掉新鲜实时数据。
- **回放自包含原始存档**：`eod/data/raw/` 保存 quotes + minutes，可离线重算，无需重抓已取不到的接口。
- **`migrate` 差异驱动 + 人工迁移分离**：自动补安全项、把改列/删列/删表留给 `db/migrations/` 人工处理，避免静默丢数据。
- **HTML 全量 `esc()` 转义**：报告渲染对动态内容做了 XSS 防护。
