## 2. 🔴 Blocker

### 2.1 gen_candidates 的日志镜像完全失效

**位置**：`gen_candidates.js:88`（log 定义）、`:324`（startRunLog 调用）；`eod/lib/runlog.js:48-51`（包装范围）

```js
// gen_candidates.js:88 —— 日志全部走 stderr
function log(...a) { process.stderr.write(a.join(' ') + '\n'); }
// gen_candidates.js:324 —— 但自镜像已开启
require('./eod/lib/runlog').startRunLog('nextday-pool');

// runlog.js:48-51 —— 只包装了 console 三个方法，stderr 完全不在镜像范围
const orig = { log: console.log, error: console.error, warn: console.warn };
console.log = wrap(orig.log); console.error = wrap(orig.error); console.warn = wrap(orig.warn);
```

**后果**：`<HOME>/eod/logs/nextday-pool-<日期>.log` 里**只有 run start 头一行**，`[1/8]~[8/8]` 的抓取进度、初筛计数、R01/R07/R05 结果、报告落点全部丢失。gen_candidates 是六个带 startRunLog 的入口里唯一不走 console 的——排障时打开日志会误判「跑过但什么都没做」。这直接违反 2026-11-10 确立的「runlog 自镜像写盘、不依赖外部重定向」约定。

**建议**（二选一，推荐 A）：
- **A. runlog 增加对 `process.stderr.write` 的包装**。注意两点：① 包装需防递归（`write` 内部用 `fs.appendFileSync`，不经 console/stderr，当前安全）；② 包装后 `store.js:26`、`pool_reflow.js:51` 等既有 `stderr.write` 告警也会进日志——这正是期望行为，不算副作用。
- B. 把 `gen_candidates.js:88` 改为 `console.error`（最省事，但以后任何人再写 `stderr.write` 都会复发——治标）。

const regime = upPctTxt == null ? b('市场宽度数据缺失', 'breadth data missing')

### 3.2 D1 HTTP 客户端无超时、无重试

**位置**：`db/d1client.js:29-37`

```js
const res = await fetch(`https://api.cloudflare.com/...`, { method: 'POST', headers: {...}, body: ... });
const j = await res.json();   // ❌ 无 signal、无重试；连接半开时 await 永不返回
```

`notify.js` 评审 #11 已为同类问题加过 15s 超时（`notify.js:70`），`pulse/lib/http.js` 的 POST 也有 timeout——唯独 D1 客户端没有。而 D1 恰好嵌在**定时链路关键路径**上：`tail_screener.emitResult → syncTailRun`、`nextday_backfill → applyTailFill` 都 `await` 它，半开连接会让 14:50 / 18:30 任务永久挂死且无任何告警。

**建议**：

```js
async function post(path, body) {
  const c = endpoint();
  for (let i = 0; i < 3; i++) {
    try {
      const res = await fetch(url, { ..., signal: AbortSignal.timeout(20000) });
      const j = await res.json();
      if (!j.success) throw new Error('CF D1 API 错误: ' + JSON.stringify(j.errors || j.messages || j));
      return j.result;
    } catch (e) { lastErr = e; await new Promise(r => setTimeout(r, 1000 * (i + 1))); }
  }
  throw lastErr;
}
```

重试安全性没问题：写入侧全是幂等 UPSERT / `INSERT OR IGNORE` / 空值保护。

### 3.3 盘前基线缓存裸写裸读，损坏即崩

**位置**：`preopen_screener.js:114`（读）、`:136`、`:220`（写）

```js
// :114 全市场路径读缓存 —— 无 try/catch
for (const [code, b] of Object.entries(JSON.parse(fs.readFileSync(cf, 'utf8')))) m.set(code, b);
// :136 / :220 裸 writeFileSync —— 崩溃留半截 JSON
fs.writeFileSync(cf, JSON.stringify(out), 'utf8');
```

**后果链**：某次 03:00 基线预计算中途崩溃/断电 → 缓存文件半截 → 次日 09:25 全市场盘前主流程 `JSON.parse` 抛错 → 整轮失败（只留一条 fail 告警），而不是降级重算。这正是 `atomic.js` 头注释描述的事故形态，但 preopen 这两处没接上。

**建议**：写用 `atomicWriteJSON(cf, out)`，读用 `readJSONSafe(cf, null, log)`，解析失败时打告警并**回退实时计算**（`computeIfMissing` 分支已有现成逻辑）。

### 3.4 盘前基线「昨日 bar」依赖 fqkline 隐式行为

**位置**：`preopen_screener.js:264`（anchor 取值）、`preopen_rules.js:84-90`（rows[0] 即昨日）

```js
anchor = tradeDate;                    // 行情日（9:25 后 = 今日）
// preopen_rules.js:84 —— 无条件把 rows[0] 当「昨日」
const y = rows[0]; const prior = rows[1];
```

`fetchKline(code, anchor)` 返回 `date <= anchor` 的全部行。**当前正确**依赖一个隐式事实：9:20–9:35 窗口内 fqkline 还不含当日 bar，`rows[0]` 恰好是昨日。两个失效场景：
1. 腾讯接口行为变化（提前给出当日竞价 bar）→ 基线把当日竞价 bar 当昨日，P2「昨日强势」全错；
2. 盘后 `--force` 补跑 → `anchor=今日`，fqkline 已含当日完整 bar，`rows[0]` = 今日 bar → **昨日涨幅=今日涨幅、竞价量比=竞价量/今日全天量**，报告口径整体失真且不报错。

**建议**：在 `getBaseline` 里对 `kl.rows` 显式过滤 `r.date < anchor` 再传 `calcBaseline`（一行改动，不依赖接口行为）；或在 `calcBaseline` 增加 anchorDate 参数并做同样过滤。顺手补一条 selftest 断言「rows 含 anchor 当日 bar 时基线不受影响」。

### 3.5 形态特征层均线逐点重算 O(n×k)

**位置**：`eod/lib/pattern_features.js:25-45`

```js
function maAt(vals, i, k) { if (i + 1 < k) return null; return mean(vals.slice(i - k + 1, i + 1)); }
// series() 对每个下标调 maAt × 4 + volMa5 × 1 → 每根 bar 重复求和
```

每只票 260 根 × 5 个序列 × 平均窗口 ~24 → 每票 ~3 万次加法 + 数千次数组切片；全市场粗筛后 ~4800 只、每次形态扫描（含 rerender 重算）都全量执行。功能正确但这是全链路最大的 CPU 热点。

**建议**：前缀和一次构建、逐下标 O(1) 取值：

```js
const ps = [0]; for (const c of closes) ps.push(ps[ps.length - 1] + c);
const maAt = (i, k) => (i + 1 < k ? null : (ps[i + 1] - ps[i + 1 - k]) / k);
```

MA5/10/20/60 与 volMa5 同法。改完跑 `npm run pattern:selftest` + `--replay` 对比重算结果一致。
