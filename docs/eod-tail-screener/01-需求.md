# 尾盘选股 · 需求

> 📌 **状态：已上线（2026-09-20 起）**。本文是**需求基线**，保留原始目标与验收标准，**不回改**。
> 上线后的实际口径、与原设计的差异见 [`05-复盘.md`](05-复盘.md)。

> **一句话**：每个交易日 **14:50（收盘前 10 分钟）** 自动跑一遍筛选，产出「尾盘走强」的候选清单，并**按同板块分组排序**，让我能横向比较同类标的、挑出最优的几只。

## 1. 定位与边界

| 项 | 说明 |
|----|------|
| 做什么 | 盘中快照筛选 → 打分排序 → 分组对比 → 生成报告 + 通知 |
| 不做什么 | 不自动下单、不接券商交易接口；不做盘口逐笔（Level-2）分析 |
| 与现有项目关系 | 复用 `candidate-pool` 的行情抓取与通知链路；**规则口径独立**（尾盘口径 ≠ R01 隔夜口径） |
| 可移植性 | 纯 Node 内建模块实现，**不调用任何 skill / 不依赖 WorkBuddy 运行时**；本地与 GitHub Actions 均可执行 |
| 数据前提（重要） | **新功能无历史样本** → 第一次运行起才有数据；因此需求里包含「结果落库 + 事后回填」，为后续复盘攒底座 |

## 2. 时间窗口

| 项 | 值 | 说明 |
|----|----|------|
| 触发时点 | 交易日 **14:50** | 收盘前 10 分钟，留出「看完还能手动操作」的时间 |
| 参考区间 | 14:30 – 14:50 | 尾盘段涨幅（尾盘异动的核心特征） |
| 跳过条件 | 周末 / 非交易日 / 非交易时段 | 由程序自行判断，不依赖外部日历接口 |
| 单次耗时 | ≤ 3 分钟 | 需在 15:00 前出结果 |

## 3. 功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-01 | 定时触发 | 交易日 14:50 自动运行；支持 `--now` 手动即时跑（用于调试 / 补跑） |
| FR-02 | 全市场快照 | 拉取全市场实时行情（价格、涨幅、成交量额、量比、换手、市值、涨跌停价） |
| FR-03 | 初筛过滤 | 按尾盘口径过滤：涨幅区间、量比、换手、市值区间；**排除** ST / 停牌 / 一字板 / 已封涨停（无法买入） |
| FR-04 | 分时校验 | 取分时数据确认：14:30→14:50 是否持续走强、当前价是否站上当日均价线、是否临近日内高点 |
| FR-05 | 板块归类 | 按所属行业分组（沿用现有自算板块强度口径） |
| FR-06 | 强度打分 | 输出可解释的分项得分与总分（便于我理解「为什么选它」） |
| FR-07 | 同类对比 | **按板块分组 → 组内按总分排序**，每组标出「组内最优」；并给出全市场 TOP N |
| FR-08 | 报告输出 | 自包含 HTML（可在浏览器 / 手机直接打开），沿用现有双语文案切换样式 |
| FR-09 | 通知 | 复用现有链路：Server酱 / PushPlus 微信 + 163 邮箱；内容为 TOP 列表 + 报告链接 |
| FR-10 | 结果落库 | 记录本次候选快照；**收盘后回填**当日收盘价、次日表现，形成可回测样本 |
| FR-11 | 幂等 | 同一交易日重复运行不产生重复记录（按 `trade_date + code` 去重） |

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 依赖 | 零第三方 npm 依赖（仅 Node 内建 `https` / `fs` / `path`），便于 GitHub Actions 直接跑 |
| 容错 | 行情接口多源回退 + 重试（沿用现有 `httpGet` 的重试与 WAF 识别逻辑） |
| 可观测 | 运行日志写文件 + 控制台输出；失败时通知里明确失败原因 |
| 配置化 | 阈值（涨幅区间、量比、换手、市值、打分权重）全部走配置文件，改阈值不改代码 |
| 可回放 | 支持 `--offline`：用落库快照重算，不依赖实时行情（便于事后复核规则改动） |

## 5. 验收标准

| # | 验收点 |
|---|--------|
| 1 | 交易日 14:50 自动产出报告，且耗时 ≤ 3 分钟 |
| 2 | 候选清单中不含 ST / 停牌 / 一字板 / 已封涨停 |
| 3 | 每只候选都能看到分项得分构成（可解释） |
| 4 | 报告按板块分组呈现，组内有序，能一眼看出「同类里谁最优」 |
| 5 | 微信 + 邮箱均收到通知，含报告入口 |
| 6 | 结果已落库；收盘后可回填实际收盘价 |
| 7 | 在 GitHub Actions 与本地各成功跑通一次 |
